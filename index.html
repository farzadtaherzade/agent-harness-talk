3 — fundamentals

سه لایه که یک مدل را به ایجنت تبدیل می‌کند

مدل موتور است، هارنس شاسی و ECU و پدال. ایجنت آن چیزی است که وقتی این دو کنار هم کار می‌کنند اتفاق می‌افتد — نه یک قطعه، یک رفتار.

۰۱ مدل تنها
یک پرامپت، یک پاسخ. نه دست، نه حافظه، نه امکان ادامه‌دادن.
۰۲ مدل + ابزار
می‌تواند بخواند و اجرا کند — اما هنوز یک‌بار: یک عمل، یک پاسخ، پایان.
۰۳ مدل + ابزار + حلقه
نتیجهٔ هر عمل برمی‌گردد. حالا می‌تواند اشتباه کند — و اصلاحش کند.
۰۴ هارنس
حلقه + سیاست + حافظه + بودجه. اینجاست که ایجنتِ آزمایشی قابل‌اتکا می‌شود.
لایهٔ ۰۱ model = f(prompt) → text — مدل تنها: خطا یعنی از صفر شروع کن؛ بین دو فراخوانی هیچ حافظه‌ای نیست.
این ایجنت نیست
  • جواب تک‌مرحله‌ای چت — یک پرامپت، یک پاسخ؛ هیچ «گام بعدی»‌ای نیست.
  • ورک‌فلو یا RAG با مسیر ثابت — مسیر از پیش نوشته شده؛ کنترلِ جریان دست مدل نیست.
  • یک پرامپت بزرگ — دستور بیشتر، اما باز هم یک‌بار و بدون ابزار.

ایجنت چیست؟

مدل = تابعی بی‌حافظه: متن در، متن بیرون. نه دست دارد، نه حافظه، نه ساعت.

ایجنت = رفتار: دنبال یک هدف، در چند گام. گام بعدی را خودش انتخاب می‌کند و خودش هم متوقف می‌شود.

هارنس = کدی که این رفتار را ممکن می‌کند: پرامپت، ابزار، حلقه، گاردریل، بودجه، حافظه، لاگ.

harness = prompt + tools + loop + policy + memory + log

این یک مدل ذهنی است، نه یک مرز جهانی: در بعضی پیاده‌سازی‌ها ابزار و حلقه داخل خودِ API مدل جای دارند و «هارنس» به بخشی از محصول تبدیل می‌شود. پس مرز میان مدل، ایجنت و هارنس را هر پروژه خودش می‌کشد.

ورک‌فلو WORKFLOW

مسیر از پیش نوشته شده. مدل فقط گاهی یک گام را پر می‌کند. خطا = شکست کل مسیر.

ایجنت AGENT

مسیر را مدل در هر لحظه انتخاب می‌کند. خطا = یک گام دیگر در حلقه، با امکان بازگشت.

نکته هر جا که مسیر قابل پیش‌بینی است، ورک‌فلو ارزان‌تر و قابل‌اعتمادتر است. ایجنت را جایی بگذارید که مسیر را نمی‌دانید.

تشبیه خودرو: موتور، ECU و دستهٔ سیم

LLM توان تولید نیرو دارد، اما بدون هارنس، خودرو حرکت نمی‌کند. مدل تعاملی را بکشید تا بچرخد و با اسکرول زوم کنید.

هارنس زنده — مدل سه‌بعدی —
موتور — هستهٔ LLM ECU — قلب هارنس LiDAR — ابزارها دستهٔ سیم — مسیر فراخوانی حافظه و وضعیت

Three.js در دسترس نبود — نمای دوبعدی جایگزین شد.
